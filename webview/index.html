🔗 Class Relationships

Four core ways objects relate to each other in real systems.

R1

Association

Generic “uses-a” link between independent objects, often many-to-many.

R2

Aggregation

Whole–part relationship where parts can live independently of the whole.

R3

Composition

Strong ownership: parts are created and destroyed with the whole.

R4

Dependency

One class temporarily depends on another (e.g. as a method parameter).

Synchronization primitives – learning path

Core building blocks to coordinate threads safely.

  1. S1

    Mutex (Mutual Exclusion)

    Single-owner lock for protecting critical sections.
  2. S2

    Semaphores

    Counting permits to control access to limited resources.
  3. S3

    Condition Variables

    Wait and signal patterns for state changes.
  4. S4

    Coarse vs Fine-grained Locking

    Balance simplicity and throughput in lock granularity.
  5. S5

    Reentrant Locks

    Allow the same thread to re-acquire the same lock safely.
  6. S6

    Try-Lock & Timed Locking

    Avoid unbounded waiting with non-blocking acquisition.
  7. S7

    Compare-and-Swap (CAS)

    Low-level atomic primitive for lock-free algorithms.

Concurrency challenges – learning path

Classic failure modes every system designer should recognise.

  1. C1

    Deadlock

    When threads wait on each other forever due to lock ordering.
  2. C2

    Livelock

    System keeps changing state but makes no real progress.

Concurrency patterns – learning path

Reusable approaches for queues, workers, and shared resources.

  1. P1

    Signaling Pattern

    Notify waiting threads when a particular condition is met.
  2. P2

    Thread Pool Pattern

    Reuse a bounded set of workers to process many tasks.
  3. P3

    Producer-Consumer Pattern

    Decouple producers and consumers using queues and signaling.
  4. P4

    Reader-Writer Pattern

    Optimise shared data access when reads dominate writes.
